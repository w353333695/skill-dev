## 画布仅三个工具节点

| 节点 | 工作内容 |
| --- | --- |
| 文件分发 | 解析所选 CMDB 文件包版本和主机，调用平台文件分发并等待完成 |
| 安装 | 调用用户选择的安装工具最新生产版本，透传目标主机、install_path 和额外参数，并轮询及读取结果 |
| 验证 | 复用统一安装后验证工具，在同一批目标主机上按需检查进程、监听端口和版本 |

三个节点均为 type=task、subtype=tool，没有 HTTP 节点、额外输入检查节点或轮询节点。平台内部 API 调用和轮询隐藏在前两个工具的实现中。

## 输入与选择器

- 文件包版本：CMDB `_ARTIFACT_VERSION`，使用简表选择，仅显示「描述 description、版本名称 versionName」；实际提交 instanceId，再读取关联包业务 ID 和版本业务 ID。候选限定文件包，不限制生产环境。
- 目标主机：HOST 多选，显示 IP、主机名；后续节点复用这批主机，不要求用户重复选择。
- 安装包存放位置：绝对路径，不能是根目录或包含 ..；统一作为 install_path 透传安装工具。
- 安装工具：工具 CMDB `_TOOL_CONFIG@EASYOPS`，简表仅显示名称；执行时使用 `$latest_production`。没有生产版本的工具不能成功执行。
- 安装工具额外参数：可选 JSON 对象。公共的 `@agents`、`install_path` 由流程统一提供，不允许额外参数覆盖。
- process_name：可空，精确匹配 Linux /proc/PID/comm。
- process_port：可空，检查本机 TCP/UDP 监听；与进程名同时填写时检查套接字归属。
- version_command、expected_version：任意一个为空，跳过版本检查；均填写时，命令退出码为 0 且输出包含期待字符串才通过。

全部验证参数为空则正常成功。验证不会对外扫描端口，版本命令应由可信用户填写。

## 离线导入

1. 解压交付 zip，在 EasyOps「自动化流程」管理页导入其中的 `.flow.tar.gz`，不要直接上传 zip。
2. API 方式：先 `POST /flows/import/check` 上传 multipart 字段 file；再 `POST /flows/v2/import`，提交 file，以及按预检结果确认的 tools、flows JSON 数组。
3. 包内根目录已包含 `_easyops_flow_info.json`、`_easyops_tar_meta.json`、`tool_batch_export.tar.gz`，工具均按流程实际引用的具体版本导出。
4. 24 环境预检 code=0，能识别三个工具及主流程；因为资源已存在，工具显示 versionExist，流程显示 verNameConflict。同环境重复导入时需确认复用工具并指定新的流程版本名；不能把 code=0 理解为可以无确认覆盖。
5. 工具使用平台注入的内部名字服务与租户用户上下文，无硬编码 24 环境 IP。跨环境导入时按平台映射处理工具/流程冲突；用户安装工具及其生产版本由用户提供，不随本包交付。
6. 未为打包擅自发布任何生产版本。辅助工具只有开发版时，平台原生导出接口存在默认生产版依赖问题，本包采用指定版本的真实批量工具导出，按原生 V2 格式组装并预检。

## 验收范围

- 最终选择器配置版本已跑通三个节点：分发成功 → 动态安装工具成功 → 版本包含匹配成功。
- 同一工具代码的前一版本已覆盖：全部验证参数为空成功；期待版本不符时，前两节点成功而验证节点失败。最终版本仅调整选择器样式与候选过滤；具体运行版本及任务 ID 见验收记录。
- 实际安装动作使用目录执行脚本工具的 `/bin/true`，不是安装真实客户端。
- 当前验证工具面向 Linux；多主机批次、进程与端口联合归属及版本命令超时仍需进一步验收。
- 选择器配置已由 Flow 回读确认，尚无浏览器逐项点击的验收证据。
- 测试只使用本次专用分发目录，未删除原有目录。生产使用前按真实安装工具的参数、权限和回滚要求补充验收。

## 失败诊断输出

- 文件分发工具失败时，输出 `deploy_failure_url` 和 `deploy_failure_log_tail`；URL 是 `https://192.168.110.24/next/file-distrubute/task/{taskId}?type=fileDelivery&event=deploy`，日志为部署任务各目标日志汇总的最后 20 行。
- 安装工具失败时，输出 `install_failure_url` 和 `install_failure_log_tail`；URL 是 `https://192.168.110.24/next/tool/task/{execId}`，日志来自工具执行日志接口的最后 20 行。
- 由于平台对失败工具可能只保留部分结构化 outputs，两个工具还会把 URL、日志尾部和原始错误拼入异常上下文，确保在执行详情 `msg` 中可见。
