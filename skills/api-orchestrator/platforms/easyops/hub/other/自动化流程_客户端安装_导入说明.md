## 三个业务阶段

1. 文件分发：CMDB `_ARTIFACT_VERSION` 单选版本；读取 `name` 作为版本 ID、`_ARTIFACT[0].name` 作为包 ID；HOST 多选主机并读取 `_uuid`；调用 EasyFlow `POST /deployTask` 并等待成功。文件包不限制环境为生产。
2. 软件安装：CMDB `_TOOL_CONFIG@EASYOPS` 选择工具，读取 `toolId`，以 `vId=$latest_production` 调用工具；透传同一批主机及安装包目录，完成轮询后读取结果。用户按需开发安装逻辑。
3. 安装后验证：在目标主机执行自带的统一验证工具，任何已启用核验失败都会令流程失败。验证工具本身引用固定开发版本，无需擅自发布生产。

画布内部为 9 个原生节点：输入选择/检查 → CMDB 版本解析 → CMDB 主机解析 → 分发 → 分发轮询 → 动态调用安装工具 → 安装轮询 → 读取安装结果 → 统一验证工具。不是三个外部脚本伪装流程。

## 参数说明

| 参数 | 含义 |
| --- | --- |
| package_version | CMDB 文件包版本选择器，API 提交值为版本实例 instanceId |
| agents | HOST 多选；API 示例为 instanceId 数组，也支持平台选择器产生的查询条件 |
| install_tool_id | 工具 CMDB 单选，平台将所选实例解析为 toolId；执行固定使用最新生产版本 |
| install_path | 文件包分发位置，必须为绝对路径；不是软件最终安装目录 |
| install_tool_inputs | 安装工具的额外 JSON 参数，默认空对象；公共主机及 install_path 由流程统一注入 |
| process_name | 可空；精确匹配 Linux /proc/PID/comm，不是正则、路径或命令行片段；注意 comm 通常至多 15 字节 |
| process_port | 可空；整数 1–65535，检查本机 TCP/UDP 监听表；同时填写进程名时检查套接字属于匹配进程 |
| version_command | 可空；在目标机 `/bin/sh` 执行，最多 30 秒；仅应填写可信的查看版本命令 |
| expected_version | 可空；版本输出中包含此字符串即通过，不做语义版本大小比较 |

空参数规则：进程名为空跳过名称检查；端口为空跳过端口检查；版本命令或期待字符串任一为空则跳过整个版本检查。全部为空也成功。端口检查只读取本机 /proc，不向外部地址发起探测。

## 离线导入

1. 解压交付 zip，选其中 `.flow.tar.gz`，不要直接上传 zip，也不要把文件名改成 V1 工具包。
2. 在“自动化流程”管理页导入原生流程包；先预检，再按提示选择工具版本与流程的导入/更新方式。
3. API 方式：`POST /flows/import/check`，multipart 字段 `file` 上传流程包；再 `POST /flows/v2/import`，同时提交 `file`、`tools`、`flows`。tools/flows 是按预检结果确认后的 JSON 数组，不应无脑覆盖已有同名资源。
4. 本包根目录已包含 `_easyops_flow_info.json`、`_easyops_tar_meta.json`、`tool_batch_export.tar.gz`。导入预检已通过文件解析；在 24 环境主流程结果 success，两个工具结果 versionExist（现有相同版本）。未为验证导入而重复创建资源。
5. 包内流程版本名规范为 `1.0.0`；运行环境保留原实际时间戳版本。若同名版本已存在，导入时指定新版本名。
6. 跨环境使用前，检查 HTTP 节点的服务 URL、Host/org/user，调整为目标部署；工具及 Flow ID 可按导入映射处理。用户安装工具需在目标环境已存在生产版本，不随本包分发。请先在开发环境验收，勿自动发布生产。
