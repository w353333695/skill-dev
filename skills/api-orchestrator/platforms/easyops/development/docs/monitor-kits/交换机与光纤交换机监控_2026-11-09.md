采集任务映射为 `ip=$.ip`、`port=$.snmpPort`；CSV 保存的是映射表达式，不是 CMDB 解析后的实际端口，不能据此认定这 4 台都是 null 端口。

### 已证实的脚本缺陷

- 主入口直接 `port=int(port)`，没有缺省/空/null 处理。离线注入 `port="null"`，在调用任何 SNMP 命令之前即抛出 `ValueError`，真实进程会非零退出。这是候选原因，不是对这 4 台实际参数的确认。
- 多个端口计数直接 `float(value)`，未统一使用已有 `_safe_float`。离线向 Brocade 分支 `port_enc_in_errors` 注入 `NA`，复现 `ValueError`，整阶段中断。
- `collect_all` 顺序执行设备、端口、流量、错误、传感器、SFP；没有阶段隔离。stdout 只在所有阶段结束后一次性输出 JSON，任一未捕获异常可能丢失此前已采到的数据。
- 顶层没有 `COLLECT_ERROR:` 和脱敏 traceback；原始异常正文无法通过约定的 stdout 通道展示。因此 `m_port_*:exit status 1` 只能证明进程异常，不能据该指标名判定仅这个指标有故障。

两项故障复现见 `development/tests/monitor-kits/test_fc_monitor_diagnostics.py`，不连接真实设备。平台默认运行环境为 Python 2；复现使用本地 Python 3 验证该两处共有的数值转换异常，不代替真机 Python 2 实采验收。

### 5 项无数据

`m_port_credit_loss`、`m_port_fec_uncorrected`、`m_port_link_failures`、`m_port_sig_losses`、`m_port_sync_losses` 在当前源码中仅由 Cisco 分支输出，Brocade 分支未实现这些输出。若这两台实际运行 Brocade 分支，这一能力差异可以解释缺项，不能伪造零值。CSV 未包含实际品牌探测结果，须补品牌/sysObjectID/脱敏调试日志后确认。

### Hub 包本身的交付风险

- 同一 ZIP 同时包含根层源码和二次嵌套的同名套件目录，存在两个不同版本的源码，不能保证导入器选择一致。
- 两份 `plugin.yaml` 的内部版本均为 `1782273797`；文件名为 v1.0.15，Hub 索引 version 为 1.0.16，版本口径不一致。
- 上述为归档检查发现，本次没有删除、覆盖或重打光交包。
