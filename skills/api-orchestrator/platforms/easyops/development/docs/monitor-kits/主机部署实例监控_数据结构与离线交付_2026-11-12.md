# 主机部署实例监控：数据结构与离线交付（2026-11-12）

## 结论

- 目标模型是 `ARTIFACT_INST@ONEMODEL`，名称“部署实例”，属于应用资源/部署资源。该模型是抽象父模型，真实实例带有 `_object_id`，本轮测试实例分别是 `MYSQL@ONEMODEL`、`REDIS@ONEMODEL`、`CLICKHOUSE@ONEMODEL`。
- 已通过 `object_attr.create` 新增 `isMonitor` 枚举字段，取值 `是/否`，默认 `否`，语义对应逻辑 true/false。
- 直接对 `ARTIFACT_INST@ONEMODEL` 执行实例 import 更新会报 `Invalid ARTIFACT_INST@ONEMODEL abstract object`。正确做法是先 search 返回 `_object_id`，再到具体子模型执行定向更新。
- 本轮已在具体子模型把 3 个测试实例更新为 `isMonitor=是` 并回读确认：MySQL `65df0395c7e4d`、Redis `65df0395e33cd`、ClickHouse `65df039607f4d`。

## 目标发现契约

- OpenAPI URI：`POST /cmdbservice/v3/object/ARTIFACT_INST@ONEMODEL/instance/_search`。
- 查询条件：`isMonitor=是` 加一个定位条件，优先部署实例 `uuid`，缺失时用 `ip`，再缺失用 `host.instanceId`；单条件是当前实现的精确主机匹配方式，不是通用安全规则。110.24历史验证中 `uuid=f907bc31-c391-4518-be14-fe50d827bfd8`、`ip=192.168.110.24` 均可命中3个测试目标。
- 返回字段：`instanceId`、`_object_id`、`installPath`、`version`、`ip`、`uuid`、`ports`、`processList`、`processMatchGroups`。
- 签名：EasyOps OpenAPI AK/SK HMAC-SHA1；请求 Host 为 `openapi.easyops-only.com`。网关必须放行该 URI，AK/SK 主体必须有模型读权限。
- 本地缓存：`<cacheDir>/<HOST.instanceId>.json`，schema version 1，包含 `refreshedAt` 与 `targets`；缺失、损坏或超过7天刷新。过期刷新失败时沿用过期缓存并输出缓存刷新失败指标，无缓存则顶层 `COLLECT_ERROR`。

## 采集与匹配

- 进程匹配优先级：`processMatchGroups.cmdline`（组内关键字全匹配）→ `processList` 的 `pname/cwd/cmdline` + `installPath` → 仅 `installPath`/cwd 兜底。
- 端口读取 `/proc/net/tcp` 与 `/proc/net/tcp6` 的 `LISTEN` 状态，并优先用匹配进程 fd 的 socket inode 关联端口；fd 不可读时退化为主机端口监听判断。
- 进程指标来自 `/proc/<pid>/stat`、`statm`、`fd`、`limits` 与 `/proc/stat`、`/proc/meminfo`，包含存活、进程/线程/僵尸数、启动时间、运行时长、内存、CPU、句柄和句柄使用率。无权限的句柄指标输出 `-1`，不伪造数值。
- 输出维度：基础维度`hostInstanceId`、`deployInstanceId`、`installPath`；进程相关指标增加`cmdline`并按命令行分组，端口相关指标增加`port`并按单端口输出；共22项原始指标。

## DEBUG日志契约（当前0.1.22）

- 开关与输出：`logLevel=DEBUG` 时诊断事件先内存缓冲，采集结束后直接输出stdout：`COLLECT_ERROR:`、逐行`[DEBUG] {json}`、`METRICS:`和指标JSON数组；失败时输出已缓冲事件与`[ERROR] {json}`致命异常。诊断不写日志文件、不写stderr，前端可直接复制完整正文给LLM跨环境调试。
- 默认`ERROR`：成功路径stdout仅输出指标JSON数组；顶层致命异常输出`COLLECT_ERROR:`与结构化错误。
- 配置与缓存：`config.ready`记录版本、日志级别、缓存目录、网关来源/协议和凭证是否已配置；`cache.check`、`cache.refresh_success/failed`记录缓存路径、年龄、目标数和刷新异常。
- OpenAPI：`openapi.start/request/response`记录脱敏URL、query、fields、分页、超时、响应code/total/返回数；失败时`openapi.request_failed/business_error/empty_diagnosis_failed`记录上下文和traceback；无目标时`openapi.no_targets`区分全局无监控实例与主机条件无匹配。
- 本地采集：`local.snapshot`、`windows.process.snapshot`、`target.start`、`port.match`、`process.refresh_stat_failed`、`process.metrics`、`port.metrics`、`target.metrics`、`target.collect_failed`、`collect.output`记录进程/端口匹配、Windows查询模式与字段缺失统计、指标值、异常兜底和22项指标覆盖统计。
- 脱敏：不输出AK/SK、签名、完整cmdline；cmdline只输出短哈希。Windows Python 2本地化traceback先安全归一为ASCII escape，避免破坏JSON日志。
