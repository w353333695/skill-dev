# IBM MQ监控模型与自动发现设计（2026-11-16）

## 结论

监控任务绑定 `HOST` 并在部署IBM MQ的Linux主机本机执行，避免新增服务模型到执行主机的关系不确定性。CMDB侧建议以「队列管理器」为最小实例粒度建立 `IBM_MQ_QMGR@ONEMODEL`；如平台已有 `IBMMQ_SERVICE@ONEMODEL`，优先复用该模型并补齐字段，避免同义模型并存。

## 模型设计

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `hostInstanceId` | string | 是 | 关联 `HOST.instanceId`，监控维度与执行定位 |
| `hostIp` | string | 是 | 主机IP；与队列管理器名组成业务唯一键 |
| `qmgrName` | string | 是 | `dspmq` 返回的 `QMNAME` |
| `installPath` | string | 否 | `dspmq`所在bin目录的上级，如 `/opt/mqm` |
| `mqBinPath` | string | 否 | `dspmq/runmqsc`所在目录 |
| `listenerPort` | int | 否 | TCP监听端口；多监听器建议建监听器子模型 |
| `listenerNames` | array<string> | 否 | 队列管理器监听器名 |
| `version` | string | 否 | `dspmqver`或安装目录元数据 |
| `environment` | enum | 否 | prod/test/uat/other |
| `isMonitor` | bool | 否 | 是否纳入监控；默认是 |
| `discoverSource` | enum | 否 | process/dspmq/manual |
| `lastDiscoverTime` | datetime | 否 | 最近发现时间 |

唯一键建议：`hostIp + qmgrName`。队列和通道不建议直接挂在服务模型上，先由监控脚本按维度输出，避免实例爆炸；确需CMDB治理时再建 `IBM_MQ_QUEUE`/`IBM_MQ_CHANNEL` 子模型。

## Linux实例定位

### 权威方法

优先执行 `dspmq -o status`，它比进程名可靠，能直接返回 `QMNAME(...) STATUS(...)`。`dspmqver` 可补版本信息。`dspmq` 常见目录：

- `/opt/mqm/bin/dspmq`
- `/opt/ibm/mq/bin/dspmq`
- `/usr/mqm/bin/dspmq`
- `$MQ_INSTALLATION_PATH/bin/dspmq`

### 进程名与cmdline规律

发现规则可用以下正则（建议大小写不敏感）：

1. 可执行名核心集：`runmqlsr|amqzxma0|amqzlaa0|amqzlsa0|amqrmppa|amqzmuc0`
2. 安装路径特征：`(^|/)(opt/mqm|opt/ibm/mq|usr/mqm)/bin/`
3. 队列管理器归属：同一cmdline中包含队列管理器名，或进程树父链命中上述核心进程。
4. 监听器端口特征：`runmqlsr.*-m\s*<QMGR>`，部分版本cmdline含 `-t TCP -p <port>`。

典型cmdline：

```text
/opt/mqm/bin/runmqlsr -m QM1 -t TCP -p 1414
/opt/mqm/bin/amqzxma0 QM1
/opt/mqm/bin/amqzlaa0 QM1
/opt/mqm/bin/amqzlsa0 QM1
/opt/mqm/bin/amqrmppa QM1
```

注意：IBM MQ后台进程名随版本和组件变化，`amq*` 不能作为唯一依据；必须结合安装路径或队列管理器名，并用 `dspmq` 校准。多实例主机的自动发现应以 `dspmq` 结果为权威，进程规则只做候选发现。

### Windows线索

服务显示名常见 `IBM MQ Queue Manager - <QMGR>`；进程名常见 `amqmsrv.exe`、`runmqlsr.exe`、`amqzxma0.exe`。本套件0.1.0脚本不支持Windows执行节点，仅可将这些规则用于CMDB发现候选。

## 发现流程建议

1. HOST侧先定位 `dspmq`，执行 `dspmq -o status`。
2. 解析 `QMNAME/STATUS`，写 `IBM_MQ_QMGR` 实例：`hostInstanceId/hostIp/qmgrName/installPath`。
3. 执行 `runmqsc <QMGR>` 的 `DISPLAY LSSTATUS(*) LISTENER PORT STATUS`，补监听器名和端口。
4. 进程规则只作为无 `dspmq` 权限时的候选信号；候选必须输出告警或标记待校准，不得直接当作实例。
5. 实例消亡时按平台保留策略处理，至少标记 `isMonitor=false`，避免误删历史告警关联。

## 指标与告警规划

指标覆盖：队列管理器状态、采集/发现成功率、队列深度/最大深度/占用率/最老消息年龄/句柄、监听器状态、通道状态/重试数/消息与字节计数、进程存活/CPU/内存/线程/句柄。

默认告警：采集失败和发现失败即时告警；队列管理器、监听器、进程和通道状态连续3点异常；通道重试连续3点；队列深度1000/5000、占用率80%/90%、最老消息300/900秒分层告警。绝对阈值必须按业务队列SLA调整。
