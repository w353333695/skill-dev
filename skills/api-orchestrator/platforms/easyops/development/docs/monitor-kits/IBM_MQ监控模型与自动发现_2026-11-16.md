# IBM MQ监控模型与自动发现设计（2026-11-16）

## 结论

监控目标不再绑定 `HOST`，绑定现网内置中间件实例模型 `IBMMQ@ONEMODEL`。该模型已继承 `ARTIFACT_INST@ONEMODEL`，由父模型提供 `ip`、`ports`、`installPath`、`processList/processMatchGroups`、`isMonitor` 与部署主机关系；不新建同义模型、不修改受保护模型。一个实例对应 `ip + name` 的一个队列管理器，`name` 必须填写队列管理器名。

## 模型设计

- `objectId`：`IBMMQ@ONEMODEL`（现网受保护内置模型）
- `name`：IBMMQ实例；实例名填写队列管理器名
- `category`：平台资源.消息队列
- `parentObjectId`：`ARTIFACT_INST@ONEMODEL`
- 业务唯一键：`ip + name`
- 监控插件绑定：`relateObjectId=IBMMQ@ONEMODEL`

| 字段 | 来源 | 说明 |
|---|---|---|
| `name` | 自动发现/人工 | 必填队列管理器名，同时作为实例展示名 |
| `name` | `dspmq` | 必填，`QMNAME`，目标队列管理器定位键 |
| `ip` | 继承部署实例 | 部署主机IP，业务唯一键与维度 |
| `installPath` | 继承部署实例 | MQ安装目录，用于推导 `<installPath>/bin` |
| `processList` | 继承部署实例 | 自动发现候选进程与执行校准线索 |
| `mqBinPath` | 任务参数 | `dspmq/runmqsc`目录；为空时按安装路径探测 |
| `ports` | 继承部署实例 | 服务端口线索；权威端口由 `DISPLAY LSSTATUS` 采集 |
| `listenerNames` | `DISPLAY LSSTATUS` | 监听器名，多个用英文逗号分隔 |
| `version` | `dspmqver` | IBM MQ版本 |
| `environment` | 人工/规则 | prod/test/uat/other |
| `isMonitor` | 发现规则 | true纳入监控；实例下线置false，不建议直接删除 |
| `discoverSource` | 发现规则 | dspmq/process/manual |
| `lastDiscoverTime` | 发现规则 | 最近发现或校准时间 |

队列和通道暂不建CMDB实例，作为监控维度输出，避免实例爆炸；确需治理时再增加 `IBM_MQ_QUEUE`、`IBM_MQ_CHANNEL` 子模型。

## 自动发现规则

### 权威定位

优先在目标主机定位并执行：

```bash
dspmq -o status
```

解析 `QMNAME(...) STATUS(...)` 后创建或更新 `IBMMQ@ONEMODEL` 实例，再执行：

```bash
runmqsc <QMGR> "DISPLAY LSSTATUS(*) LISTENER PORT STATUS"
```

补充监听器名和端口。`dspmq` 常见目录：Linux常见目录：`/opt/mqm/bin`、`/opt/ibm/mq/bin`、`/usr/mqm/bin`、`$MQ_INSTALLATION_PATH/bin`；Windows常见目录：`C:\Program Files\IBM\MQ\bin`、`C:\Program Files (x86)\IBM\MQ\bin`，命令名为 `dspmq.exe/runmqsc.exe`。

### 进程与cmdline候选

进程发现建议大小写不敏感，并组合以下条件：

1. 可执行名核心集：`runmqlsr(.exe)?|amqmsrv(.exe)?|amqzxma0(.exe)?|amqzlaa0(.exe)?|amqzlsa0(.exe)?|amqrmppa(.exe)?|amqzmuc0(.exe)?`
2. 安装路径特征：`(^|/)(opt/mqm|opt/ibm/mq|usr/mqm)/bin/`
3. 队列管理器归属：cmdline包含队列管理器名，或进程树父链命中核心进程
4. 监听器定位：`runmqlsr.*-m\s*<QMGR>`，部分版本附带 `-t TCP -p <port>`

典型cmdline：

```text
/opt/mqm/bin/runmqlsr -m QM1 -t TCP -p 1414
/opt/mqm/bin/amqzxma0 QM1
/opt/mqm/bin/amqzlaa0 QM1
/opt/mqm/bin/amqzlsa0 QM1
/opt/mqm/bin/amqrmppa QM1
```

`amq*` 进程名随版本和组件变化，不能单独作为实例判定；进程规则只产生候选，必须用 `dspmq` 校准后写CMDB。Windows候选线索：服务名 `IBM MQ Queue Manager - <QMGR>`，进程 `amqmsrv.exe/runmqlsr.exe/amqzxma0.exe`；Windows监控脚本通过PowerShell CIM采集进程资源，PowerShell不可用时降级WMIC获取进程候选。自动发现规则、命令探测、readme、插件memo和离线回归均必须同时覆盖Linux与Windows；后续任何指标或采集路径优化均不得删除双平台回归。

## 发现流程

1. 按HOST进程/端口或部署实例缓存定位IBM MQ候选主机。
2. 在候选主机执行 `dspmq -o status`，按 `ip+QMNAME` upsert `IBMMQ@ONEMODEL`。
3. 从命令绝对路径推导 `mqBinPath/installPath`，从 `LSSTATUS` 补监听器。
4. 写入 `discoverSource=dspmq`、`lastDiscoverTime`、`isMonitor=true`。
5. 无 `dspmq` 执行权限时只输出process候选告警，不直接创建正式实例。
6. 实例消失时置 `isMonitor=false`并保留历史实例，等待平台保留策略归档。

## 指标与告警

监控基础维度：`ibmmqInstanceId/qmgrName/hostIp/installPath`。0.4.0共45个别名指标、11个指标集，覆盖队列管理器状态、目标匹配/采集成功、本地/传输/死信队列深度与占用率、最老消息年龄、队列句柄、GET/PUT状态、监听器、通道状态/重试/消息数/收发字节数和进程资源。

### 队列分类与死信队列定位

0.4.0通过一次 `runmqsc` 批量命令获取队列定义、队列状态、通道状态和监听器状态：

```text
DISPLAY QMGR DEADQ
DISPLAY QLOCAL(*) CURDEPTH MAXDEPTH USAGE GET PUT
DISPLAY QSTATUS(*) CURDEPTH MSGAGE IPPROCS OPPROCS
DISPLAY CHSTATUS(*) CHLTYPE STATUS MSGS MSGNO BYTES BYTSRCVD BYTSSENT
DISPLAY LSSTATUS(*) LISTENER PORT STATUS
```

- 死信队列：先解析 `DISPLAY QMGR DEADQ`，再按队列名精确匹配；默认 `SYSTEM.` 前缀排除规则对该队列失效，保证 `SYSTEM.DEAD.LETTER.QUEUE` 等系统死信队列强制纳入。
- 传输队列：解析 `USAGE(XMITQ)`，输出传输队列深度、最大深度、占用率、GET/PUT。
- 本地队列：非传输队列且通过名称过滤；输出深度、最大深度、占用率、最老消息年龄、输入/输出句柄、GET/PUT。
- 通道流量：优先解析 `BYTSRCVD/BYTSSENT`，同时保留旧字段 `BYTES` 兼容。

### Zabbix阈值对齐

参考源为Zabbix 5.4导出目录 `apps/zabbix-template-export/zabbix54_20261112_144121_866000` 中 `TEMP_PBC_MID_IBMMQ_CUSTOM`、`TEMP_PBC_MID_IBMMQ_CUSTOM_LOW`、`TEMP_PBC_MID_IBMMQ_LOG` 相关模板、监控项原型和触发器原型。

| 对象 | Zabbix规则 | 0.4.0告警模板 |
|---|---|---|
| 本地队列占用率 | Warning `>=80%` 且 `<90%`，Critical `>=90%` | 80% Warning、90% Critical |
| 传输队列占用率 | Warning `>=80%` 且 `<90%`，Critical `>=90%` | 80% Warning、90% Critical |
| 死信队列深度 | `CURDEPTH > 0` 且连续2点 | 连续2点大于0，Critical |
| 队列管理器状态 | 非 `Running` 即触发，Critical | 单点非Running，Critical |
| 监听器状态 | 非 `Running` 即触发，Critical | 单点非Running，Critical |
| 通道状态 | 多个模板存在Warning/严重差异，并带连续次数/状态窗口 | 连续3点非Running，Warning |
| GET/PUT状态 | 导出触发器为disabled | 仅采集展示，不默认告警 |

目标匹配失败、采集失败保持即时告警；进程不存活和通道重试保持连续3点；队列绝对深度1000/5000、最老消息300/900秒是Zabbix导出外的补充策略，生产上线前必须按业务队列SLA调整。
