# 物理服务器 IPMI 监控：离线交付

## 范围与状态

- 用户确认：Linux x86_64 与 ARM64，Python 2.7 优先，纯 Python 实现优先；仅离线交付。
- 套件版本：0.1.0。新商品，未修改已有 SNMP/Redfish 套件、模型或平台任务。
- 模型：目标平台已有 `PHYSICAL_SERVER@ONEMODEL`；不附模型覆盖文件。
- Hub 包：`监控套件_物理服务器IPMI监控_0.1.0.zip`。
- 本次未连接真实 BMC、未调用导入/激活接口，无前端实例 ID，不能提供已验收实例 URL。

## 实现与依赖

- 原始源码：`development/monitor-kits/physical-ipmi-monitoring/src/ipmi_monitor.orig`。
- 构建器：`development/scripts/build_ipmi_monitor_kit.py`；从 `.orig` 生成注入了所有参数的 `.py`。
- 后端：pyghmi 1.5.61 会话/SDR 子集、pyaes 1.6.1、six 1.17.0，均保留原始许可证。
- `vendor/x86_64/dependencies.zip` 与 `vendor/arm64/dependencies.zip` 均是完整纯 Python 依赖子集，内容相同，架构清单分别标识。
- pyghmi 局部补丁：AES-CBC 后端换为 pyaes；禁止 IPMI 1.5 降级；移除远控示例入口；让 `pause()` 传播超时；认证错误经回调而非 stdout 打印。
- 未重新实现 AES 算法，保留 IPMI 特定填充，未加入 PKCS7。NIST SP800-38A F.2 两块 AES-CBC 向量及 IPMI 填充往返均测试。
- 不携带 cryptography/cffi/dateutil，不安装系统依赖，不通过 `ipmitool` 执行，不支持 OEM 私有指标。
- 纯 Python AES 不是恒定时间实现；Python 2 和所选协议库已老旧，仅面向受控授权管理网的遗留运行环境。

## 指标与安全

- 16 个原始指标，统一 `physical_ipmi_` 前缀；中文别名、指标集统一“物理机IPMI-”。
- BMC会话、机箱电源、传感器数量/可用性/健康位掩码，以及真实单位匹配的温度、RPM、电压、功率、电流、百分比。
- `ip` 用于关联物理机，`bmc_ip` 必须显式填写；不自动将业务 IP 当作 BMC 目标。
- 通用 SDR 解析负责缩放与状态；不从传感器名称猜单位。单位 `C` 表示库中的库仑，不能错误映射成摄氏温度。
- 读数不可用不补数值 0、不输出虚假健康；健康位掩码沿用库的 0/1/2/4 及组合值。
- 缺失/未知单位不强行转换；`collect_complete` 表示流程完成且无读取异常，不代表所有硬件健康。
- 业务命令只读白名单；默认 USER(2)，可选 OPERATOR(3)，不申请 ADMIN；协议会话协商、SDR预留和注销不属于硬件配置修改。
- 认证预检查默认 5 秒，一次登录尝试，协议重传受此时限约束；整轮默认 60 秒，另有最多 2 秒注销时间。
- 正常 stdout 为纯 JSON；入口错误输出脱敏 `COLLECT_ERROR` 与 traceback 后退出 0。登录失败记录 `available=0`、错误数和脱敏摘要；局部读取失败保留其他读数。
- 日志默认 ERROR；DEBUG 可看白名单只读命令原始响应，不输出认证握手密钥，密码/KG/用户名及常见转义形式均脱敏。

## 参数约定

套件参数统一使用 `string` 类型，包括端口、超时、权限以及用户名、密码、KG。所有参数均配置 `isFromSecret=false`、`isEncrypt=false`；CMDB 动态属性只负责提供原始字符串，脚本内部负责数值转换与校验。

## 告警

包内 JSON 和 CSV 配套使用 `diff` 状态变化规则，包含 BMC可用、传感器可用/健康、采集完整性和机箱电源。

这是状态变化通知，不是持续故障判断；首次采样已故障不保证触发。无数据需要单独配置平台无数据策略。未预置跨品牌通用温度/风扇/电压阈值。

## 离线验证证据

执行环境 Linux x86_64，CPython 2.7.18（项目内源码构建，仅作测试工具）和系统 Python 3.11.2。

- 两种解释器各 30 项 unittest 通过。
- 覆盖真实 SDR 二进制解析、NIST AES-CBC、IPMI 填充、禁止降级、只读命令拒绝、模拟采集成功/失败/局部失败、真实本地信号超时、脱敏、参数缺失/空值/None、stdout 协议、依赖SHA256、元数据引用和 `.orig` 重生成。
- 专门复现上游 `pause` 吞掉超时并污染 stdout，回归先失败、补丁后通过。
- 目录及 ZIP 通过现有 `validate_monitor_kit.py` 校验，16 项指标。
- ZIP 顶层名与套件名一致；目录先于文件，目录0755/文件0664；外层 ZIP_STORED；不含测试、缓存和构建材料。
- ARM64 仅验证依赖纯 Python 与架构选择逻辑，未在 ARM64 实机执行。未做真实 BMC 或 EasyOps 导入/激活验收。
- 最终 Hub ZIP 重新解压后，两种解释器各30项回归再次通过。全平台 lint 仍报告40项存量错误（主要是既有Hub脚本索引登记问题），与主工作区对照未发现本次新增错误；未擅自修复无关资产。

## 重建与回归

以工作空间根为 cwd，在项目内缓存放入 `build-support/dependencies.lock.json` 固定的三份源码归档。下载优先使用镜像，构建器按已提交的官方源码 SHA256 校验，不信任临时修改的包摘要。

```sh
python3 skills/api-orchestrator/platforms/easyops/development/scripts/build_ipmi_monitor_kit.py \
  --cache projects/api-cli/.local/ipmi-deps --output tmp/ipmi-monitor/rebuild
IPMI_KIT_ROOT="$PWD/tmp/ipmi-monitor/rebuild/物理服务器IPMI监控" PYTHONDONTWRITEBYTECODE=1 \
  python3 skills/api-orchestrator/platforms/easyops/development/tests/monitor-kits/test_ipmi_monitor.py
```

用 Python 2.7 解释器重复第二条命令；不需要为 skill 建 venv 或安装第三方包。包内 `--doctor` 不连接设备。构建器拒绝已有套件目录，避免混入旧产物。
