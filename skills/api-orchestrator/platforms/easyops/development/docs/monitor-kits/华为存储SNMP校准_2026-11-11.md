# 华为存储 SNMP 校准验收

## 输入证据

用户提供 `tmp/hw-snmp-result.txt`（3121 行），sysObjectID 为 `enterprises.2011.2.91`，主数据位于 `34774`；设备版本字段为 `6.1.2.SPH63`。不根据设备自定义名称猜型号。单位与硬件字段对照 `apps/zabbix-template-export/zabbix54_20261104_104150_596000/templates.json` 中 5500v6 模板。该模板存在个别字段重复，不能原样全量照搬。原始文件不提交，回归 fixture 只保留容量、状态、资源标识、控制器利用率，不保留 IP、MAC、序列号、板卡详情或凭证。

## 修复

- 身份根补充 `1.3.6.1.4.1.2011.2.91`，与实际数据根 `34774` 独立；OID 前缀必须按段匹配，避免 91 匹配 910。
- 原解析器从任意文本搜索数字，OID 文本可能被截成 2 或 1.3；现按 ASN.1 类型解析，OID/字符串保留内容，Counter64 直接转整数。
- No Such Object/Instance、NULL、MIB 结束视为缺失；不输出 None、假零、假成功。基础系统对象均缺失时报 COLLECT_ERROR。
- 原表解析只取末段索引，会把不同磁盘合并；现保留列 OID 后完整复合索引并校验列前缀。
- 华为阵列和池容量依据模板乘 1048576 转成字节，并在相同资源维度输出容量、已用量和百分比。
- 控制器、磁盘、池、电源、风扇、电池、机框按模板采健康状态；控制器额外采 CPU/内存使用率。原告警 JSON/Excel 的现有阈值保留，未擅自增加 CPU/内存阈值。
- LUN 名称发现改用 `34774.4.1.23.4.8.1.2`；未增加 LUN 性能和 NAS 文件系统容量，不猜 KB/MB 单位及跨表关联。
