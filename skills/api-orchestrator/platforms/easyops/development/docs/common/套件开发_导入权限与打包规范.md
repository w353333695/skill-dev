# 套件开发：导入权限与打包规范

## 结论

EasyOps 采集/监控套件导入出现 `open PHYSICAL_SERVER@ONEMODEL.json permission denied` 时，优先检查 ZIP 的目录项顺序、目录权限、文件权限和包内根目录名称。不要只重试导入，也不要把问题归因于 JSON 内容。

## 必须满足

1. ZIP 顶层只有一个与 `plugin.yaml` 的 `name` 完全一致的根目录。
2. ZIP 条目顺序必须是：根目录 → 子目录 → 文件；不要先写文件、最后补目录项。部分 `collector_plugin_service` 导入器按 ZIP 顺序创建和校验路径，目录项在文件之后可能导致文件打开时被报告为 `permission denied`。
3. 目录权限使用 `0755`，文件权限使用 `0664`；文件不能是软链接、设备文件或不可读文件。
4. `PHYSICAL_SERVER@ONEMODEL.json` 等关联模型文件放在根目录，文件名保持原样；包内路径不要带绝对路径或多余层级。
5. 包内不要包含 `__pycache__`、测试目录、临时文件或旧版同名文件。
6. 打包后必须从 ZIP 重新检查条目顺序和权限，不能只检查本地源目录。

## 推荐校验

```python
import stat, zipfile
with zipfile.ZipFile("套件.zip") as package:
    entries = package.infolist()
    assert entries[0].filename.endswith("/")
    assert "__pycache__" not in "\n".join(item.filename for item in entries)
    for item in entries:
        mode = stat.S_IMODE(item.external_attr >> 16)
        if item.is_dir():
            assert mode == 0o755
        else:
            assert mode == 0o664
```

Windows 本地目录权限不能代表导入环境权限；必须以 ZIP `external_attr` 为准。导入失败后先下载/解压复核，修复后自增版本重新打包，Hub 只保留最新成品。
