# 套件开发：导入权限与打包规范

## 结论

EasyOps 采集/监控套件导入出现 `open PHYSICAL_SERVER@ONEMODEL.json permission denied` 时，优先检查 ZIP 的目录项顺序、目录权限、文件权限和包内根目录名称。不要只重试导入，也不要把问题归因于 JSON 内容。

## 必须满足

1. ZIP 顶层只有一个与 `plugin.yaml` 的 `name` 完全一致的根目录。
2. ZIP 条目顺序必须是：根目录 → 子目录 → 文件；不要先写文件、最后补目录项。部分 `collector_plugin_service` 导入器按 ZIP 顺序创建和校验路径，目录项在文件之后可能导致文件打开时被报告为 `permission denied`。
3. 目录权限使用 `0755`，文件权限使用 `0664`；文件不能是软链接、设备文件或不可读文件。
4. `PHYSICAL_SERVER@ONEMODEL.json` 等关联模型文件放在根目录，文件名保持原样；包内路径不要带绝对路径或多余层级。
5. 包内不要包含 `__pycache__`、测试目录、临时文件或旧版同名文件。
6. 打包后必须从 ZIP 重新检查条目顺序和权限，不能只检查本地源目录。

## 指标集定义结构

监控套件的 `metric_set.json` 必须是非空对象数组，每个元素至少包含非空 `name` 字段，例如 `[{"name":"基础指标"}]`；不能写成纯字符串数组。`alias_metric.json` 的 `metricSet` 引用必须能命中这些 `name`。打包和导入前必须运行 `development/scripts/validate_monitor_kit.py`，防止指标集实例未生成导致前端创建任务时无法加载指标集。
导入后还必须回读 `_COLLECTOR_EASYOPS_PLUGIN.relateMetricSets`，确认指标集实例 ID 与 `metrics` 映射已落库；不能只看 `/api/v1/plugin/metrics/list` 或导出包中的 JSON。
指标、维度或指标集定义在 `import_update` 后发生变更时，必须执行官方 `kit.activate` 刷新监控资源。刷新指标定义可使用 `notRequireJob=true`、`needUpdateJob=false`，避免更新已有采集任务；如需更新任务，必须先确认影响。激活后回读 `_COLLECTOR_ALIAS_METRIC.dims`、插件 `relateMetricSets` 与指标集映射，确认新维度进入别名指标目录；不要优先直接改 CMDB。
用户手填 AK/SK 等任务凭证常规使用`valueType=password`且`isEncrypt=true`、`isFromSecret=false`。如需验证`valueType=string`、`use=collectorParams`、`isFromSecret=true`、`isEncrypt=true`的Secret/collectorParams链路，必须升级后回读线上参数，并用`debug-collector-job`确认注入结果；未完成真实调试前不得把该试验态推广为通用规范。`import_update`会按同名参数继承旧标志；历史标志错误时应更名参数做原生迁移，升级后回读线上参数配置。

## 推荐校验

```python
import stat, zipfile
with zipfile.ZipFile("套件.zip") as package:
    entries = package.infolist()
    assert entries[0].filename.endswith("/")
    assert "__pycache__" not in "\n".join(item.filename for item in entries)
    for item in entries:
        mode = stat.S_IMODE(item.external_attr >> 16)
        if item.is_dir():
            assert mode == 0o755
        else:
            assert mode == 0o664
```

Windows 本地目录权限不能代表导入环境权限；必须以 ZIP `external_attr` 为准。导入失败后先下载/解压复核，修复后自增版本重新打包，Hub 只保留最新成品。

## 监控套件 Python 源码与 `.orig` 配套文件

`simple-script` 监控套件的每个 Python 采集脚本必须同时交付同名 `.orig` 文件：

- `src/<script>.py` 是平台实际执行文件，必须通过 `EASYOPS_COLLECTOR_<param>` 读取任务参数；平台注入参数时只能在 shebang/编码声明之后插入，不能破坏 Python 2 编码声明。
- `src/<script>.orig` 是未注入参数的原始源码，文件名与 `.py` 基名完全一致；用于平台重新注入、导入失败回溯和离线审计。
- `.orig` 与 `.py` 必须保持同一版本源码逻辑；如果 `.py` 仅增加环境变量注入段，除注入段外正文应与 `.orig` 一致。
- ZIP 禁止包含 `src/__pycache__/`、`.pyc`、测试目录和临时文件；打包校验必须确认 `.orig` 存在、可读且与目标 `.py` 的非注入正文一致。

缺少 `.orig` 可能导致套件导入器报“没有 orig 文件”或无法生成带环境变量的执行脚本。

## Python 脚本参数注入顺序

环境变量取参代码不能无条件拼到脚本最前面。Python 2 的编码声明必须位于第一行，或在第一行是注释（例如 shebang）时位于第二行。正确顺序为：

```python
#!/usr/local/easyops/python/bin/python
# -*- coding: utf-8 -*-
import os
host = os.environ.get("EASYOPS_COLLECTOR_host")
```

2026-11-05 复核 Redfish 旧包发现，注入段在编码声明前，导致声明不再有效；含中文源码在 Python 2 中可能报 `SyntaxError: Non-ASCII character`。修正发布 `.py` 时保留文件头，再插入取参代码；`.orig` 保留未注入正文，也必须保留有效编码声明。平台若根据 `.orig` 重新生成 `.py`，还应检查其生成结果，不能只验证上传前文件。

打包回归应直接读取 ZIP 内原始字节，检查 shebang、编码声明所在行与注入顺序；不能仅将源码先解码成 Unicode，再用 Python 3 `compile()` 通过就声称兼容 Python 2。没有 Python 2 解释器时明确标记未完成真实 Python 2 运行验证。
