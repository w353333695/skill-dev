# Zabbix 5.4 全域监控数据只读导出（2.0.0）

导出当前账号可见的监控配置，回答“什么对象、哪些 IP、配置了哪些监控和指标、什么条件告警”。不再仅导出模板，也不限于进程/端口场景。

## 运行方式

- Python 2.7.9+：`python2 export_zabbix54_templates_py2.py`，该文件可独立使用。
- Python 3.9+：`python3 export_zabbix54_templates.py`，必须携带同目录 `export_zabbix54_templates_py2.py`，两入口共用引擎，避免功能漂移。
- 无第三方依赖；`-h` / `--help` / `--version` 不联网。
- 所有 API 业务操作均为 `.get` 或 `configuration.export`；使用账号密码时另有登录/注销，不修改 Zabbix 配置、不连接被监控主机、不执行脚本或探测端口。

修改**所运行入口脚本**顶部变量后执行。不把密码放进命令行、群聊或交付文档，优先使用只读 Token；密码默认留空。脚本不读取系统环境中的凭证，不自动保存登录 Token。

```python
ZABBIX_URL = "https://zabbix.example/zabbix"
ZABBIX_TOKEN = ""       # 本地配置：非空优先，使用Token时无需填写用户名/密码
ZABBIX_USER = "Admin"
ZABBIX_PASSWORD = ""    # 仅当不使用Token时本地填写；配置文件本身须妥善保管
OUTPUT_DIR = "./exports"
TIMEOUT = 120
INSECURE = False
EXPORT_ALL = True
TEMPLATE_IDS = []
TEMPLATE_NAMES = []
EXPORT_HOSTS = True
HOST_IDS = []
BATCH_SIZE = 25
EXPORT_EXTENDED = True
FAIL_ON_PARTIAL = True
EXPORT_EVENTS = True
EXPORT_HISTORY = False
EXPORT_TRENDS = False
EXPORT_TEXT_HISTORY = False
DATA_TIME_FROM = None
DATA_TIME_TILL = None
PAGE_SIZE = 5000
```

`OUTPUT_DIR` 默认是入口脚本所在目录的 `exports/`。每次建立新时间戳目录，不覆盖旧导出。JSON、CSV、JSONL 文件创建权限为 0600，目录 0700；Windows 等平台权限语义按操作系统为准。

## 导出范围

| 范围 | 主要产物 | 内容 |
|---|---|---|
| 主机 | `hosts.json`、`主机清单.csv` | 技术名/显示名、状态、全部接口 IP/DNS/端口、接口类型、主机组、标签、资产清单、宏、直接模板、代理关联 |
| 模板 | `templates.json`、`templates-api.json`、`template-index.json` | 原生模板导出、模板属性、父模板、模板宏；保留旧版文件名 |
| 关联 | `host-template-links.json` | 主机直接模板、递归继承模板及不可见父模板 ID |
| 指标 | `items.json`、`主机监控项清单.csv` | 主机及模板监控项，包括继承项、原始 key、解析后 key、周期、类型、单位、状态、错误、预处理、值映射、依赖项；API 自带最新值字段会保留，但不另外拉取历史 |
| 告警 | `triggers.json`、`主机告警阈值清单.csv` | 原始告警/恢复表达式、函数、关联指标、宏解析后的可读表达式、未解析宏、严重性、状态、依赖和标签 |
| 发现 | `discovery-rules.json`、`item-prototypes.json`、`trigger-prototypes.json`、`host-prototypes.json` | LLD 过滤、覆盖、宏路径、预处理、监控项/触发器/主机原型 |
| 图形/Web | `graphs.json`、`graph-prototypes.json`、`web-scenarios.json` | 图形及原型、Web 场景和步骤 |
| 公共配置 | `host-groups.json`、`value-maps.json`、`global-macros.json` | 组、值映射及宏；5.4 使用标签组织监控项，不调用已移除的 application.get |
| 告警路由 | `actions.json`、`media-types.json`、`correlations.json` | 动作过滤/操作/恢复/确认操作、媒体类型及消息模板、事件关联；联系人和凭证不导出 |
| 其他配置 | `maintenance.json`、`proxies.json`、`network-discovery.json`、`services.json`、`maps.json`、`dashboards.json`、`scripts.json`、`images.json` | 维护窗口、代理、网络发现、IT 服务、拓扑图、仪表盘、脚本定义及图片；只读取定义，不执行 |
| 网络发现结果 | `discovered-hosts.json`、`discovered-services.json` | 已有发现主机和服务结果，不触发新探测 |
| 事件/通知 | `operational/events-*.jsonl`、`problems-*.jsonl`、`alerts-*.jsonl` | 触发器、发现、自动注册、内部事件及其问题/通知记录；由 `EXPORT_EVENTS` 单独控制 |
| 指标历史（可选） | `operational/history-<itemid>.jsonl` | 指标原始采样值，默认关闭 |
| 趋势（可选） | `operational/trends-<itemid>.jsonl` | 数字指标趋势汇总，默认关闭 |
| 完整性 | `export-manifest.json`、`data-scope.json` | 各数据集 API、成功/部分失败、数量、错误、时间范围、开关和范围限制 |

`alert-rules.json` 保留旧版聚合结构，便于旧处理程序继续读取。CSV 为 UTF-8 BOM，可直接用 Excel 打开；这些是分析清单，不是 EasyOps 告警规则导入模板。

## 本次所需的进程/端口清单

`主机进程端口清单.csv` 直接关联真实主机 ID、技术名、首选接口 IP/DNS、itemid、进程名参数、命令行匹配、用户限制、协议/服务、检查地址、端口和触发器 ID。

识别 `proc.num`、`proc.cpu.util`、`proc.mem`、`net.tcp.listen`、`net.udp.listen`、`net.tcp.port`、`net.tcp.service`、`net.tcp.service.perf`。保留原始 key，解析引号内的逗号。自定义 UserParameter、脚本或其他插件监控项仍在通用指标清单中，不根据名称猜测其进程和端口。

主机可能有多个接口，CSV 中的“首选接口”优先 Agent 主接口，再回退其他类型；完整接口始终保留在 `hosts.json`。`useip=0` 时实际连接使用 DNS，IP 字段可能不是实际连接地址。某监控项指定哪个接口，应看 `interfaceid`，不能把首选 IP 当成所有监控项的目标。

模板名称不是主机名称，模板 ID 也不是实际主机 ID。进程命令行匹配条件不等于真实可执行文件名或 PID，端口监听项也不能证明进程归属。

## 阈值与宏

- 保留原始 `expression`、`recovery_expression` 和函数引用，不用比较运算符加数字的简单正则“猜阈值”。
- 可读表达式利用 `functions/itemid` 展开关联指标；保留原文供核验。
- 宏按主机、近层父模板、远层父模板、全局的顺序尝试解析；同层冲突、未知/嵌套未解析宏、上下文匹配和密钥宏不推测。
- 跨多主机表达式不使用某一台主机的宏覆盖整个表达式，保持原式并注明未解析宏。
- API 权限不足、父模板不可见、宏覆盖或表达式复杂时，以原始 JSON 为准。可读表达式用于分析，不是可直接回写的告警配置。

## 历史、趋势和事件

监控指标的历史值和趋势汇总默认均不导出。需要时分别启用 `EXPORT_HISTORY`、`EXPORT_TRENDS`；文本、字符、日志历史可能含敏感信息，另需显式启用 `EXPORT_TEXT_HISTORY`。

`DATA_TIME_FROM/TILL` 使用 Unix 秒时间戳。`None` 表示从全部仍保留数据的起点导出到本次开始时间。生产环境建议先限定一天或一周，评估数据量后扩大范围，避免对服务造成过大负载。指标历史按实际主机监控项分别导出，JSONL 流式写入，不把所有历史放入内存。

事件用 ID 游标继续拉取，不因一页数量达到上限就截断。历史、趋势、通知记录按时间范围二分；如果同一秒达到 `PAGE_SIZE`，标记不完整并提示提高上限，不静默丢数据。若服务端存在低于 `PAGE_SIZE` 的额外响应截断，需调整服务端限制并核对数量；脚本不能从受限响应中证明全量。

## 完整性、权限与安全边界

- “全量”指本文列出的、**当前账号和 Zabbix 5.4 API 可见**的数据域，不是数据库备份。不能恢复被清理的历史数据、已删除对象，也不保证插件私有数据或仅数据库存储的全局设置可通过 API 导出。
- 不导出用户/用户组/联系人、登录密码、Token、PSK、SNMP 密钥、审计日志等敏感内容。结构化凭证字段、密钥宏会脱敏；废弃旧版 `INCLUDE_SENSITIVE=True` 的明文导出路径。自由文本、脚本正文、自定义键可能嵌入未识别的敏感内容，导出文件仍须按内部敏感资料管理，分享前人工检查。
- 一个 API 失败不终止其他独立数据集；错误含函数标记和脱敏 traceback。`export-manifest.json` 将失败项标为 `partial`，不伪造完整成功。
- 默认 `FAIL_ON_PARTIAL=True`：完整请求成功退出 0；部分失败退出 2；致命失败退出 1；中断退出 130。退出 0 也不能证明账号具有全组织可见权限。
- `EXPORT_EXTENDED=False` 可关闭公共扩展数据集；`EXPORT_HOSTS=False` 停止主机及其监控项导出，不影响公共配置或独立的事件开关。`TEMPLATE_IDS/NAMES` 非空时优先筛选模板并补齐父模板；都为空时 `EXPORT_ALL=True` 才选择全部模板。该筛选仅限制模板导出；`HOST_IDS` 独立限制主机。公共配置仍导出可见全集，不把模板筛选误当作主机授权范围。
- API 并非事务快照，导出期间的主机、模板、指标和事件变更可能产生时间差异。每次使用新目录，避免污染旧快照。
- 不自动读取或输出本地系统凭证；Token/密码仅用于向用户明确配置的 Zabbix API 认证；禁止重定向转发认证信息。
